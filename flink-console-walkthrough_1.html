MyNotebook — Apache Zeppelin Flink 1.20

Run a query, watch results arrive as the stream moves.

Step 1 · declare the source table

Flink SQL can't query a stream until a table is declared on top of it. This DDL is also where the poison-pill defense lives — keep an eye on the format options.
%flink.ssql(type=update)
CREATE TABLE market_ticks (
  ticker VARCHAR,
  price DOUBLE,
  event_time VARCHAR
) WITH (
  'connector' = 'kinesis',
  'stream' = 'market-ticks-input',
  'aws.region' = 'us-east-1',
  'scan.stream.initpos' = 'LATEST',
  'format' = 'json'
);

Step 2 · query it, continuously

%flink.ssql(type=update)
SELECT ticker, price, event_time
FROM market_ticks
WHERE price > 100.0;

Scaling & parallelism

This is the "serverless" part — AWS adjusts compute to match load.

Parallelism configuration

How many parallel tasks run. Benefits from multiple shards, KeyBy operations, or multiple window operators — can't usefully exceed the source's shard count without resharding.
Default is 1. Raise it only if an operator needs more memory per subtask than one KPU provides — that trades off KPU count for per-task headroom.

Scaling

Each KPU bundles compute + memory. AWS scales the KPU count up or down automatically as source throughput changes — this is what you're paying for, and only for what's running.

▸ Why does it loop forever instead of just skipping the bad record?
Managed Service for Apache Flink restarts a failed job from its last checkpoint to preserve exactly-once semantics — but that checkpoint's stream position is still sitting right before the poison pill. The job replays the same record, fails the same way, and restarts again.
▸ Already stuck in the loop right now — how do you get out?
Fixing the DDL won't help an app that's already restarting from a bad checkpoint. Stop it, then Run again choosing a fresh stream starting position (LATEST, or AT_TIMESTAMP just past the bad record) instead of restoring the last snapshot.
▸ Using the DataStream API instead of SQL?
DeserializationSchema can't emit to a side output. The pattern there is deserialize() returning null to drop silently, or wrapping results in an Either<Good,Bad> type and splitting downstream with a ProcessFunction + OutputTag into a dead-letter stream.
